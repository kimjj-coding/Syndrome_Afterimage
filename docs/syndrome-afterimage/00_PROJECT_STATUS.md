# 프로젝트 상태와 미결정 사항

**상태:** 조사 중 · 최종 게임 기획 확정 전  
**제품 형태:** 브라우저 기반 웹 게임  
**개발 조건:** 초보자, 비용 최소화, 작은 검증 단위 우선

## 확인된 프로젝트 제약

- 웹 브라우저에서 실행하는 게임을 목표로 한다.
- 조사 결과는 Copilot 등 AI 코딩 도구가 작은 기능을 안전하게 구현할 수 있는 명세로 정리한다.
- 사용자가 명시적으로 승인하지 않은 엔진·카메라·조작·스토리·엔딩을 확정하지 않는다.
- 사실, 해석, 가설, 보류를 문서와 구현 요청에서 구분한다.

## 미확정 사항

| 항목 | 현재 상태 | 결정 전에 필요한 것 |
|---|---|---|
| 엔진/프레임워크 | 보류 | 같은 기능을 구현한 작은 POC와 작업량 비교 |
| 카메라/시점 | 보류 | 핵심 상호작용이 시점 선택에 실제로 어떤 요구를 만드는지 |
| 입력 | 보류 | 키보드·포인터, 필요 시 터치의 최소 요구와 접근성 검사 |
| 스토리/캐릭터/세계관 | 보류 | 핵심 루프와 표현 원칙이 안정된 뒤 연결 |
| 추격/은신 | 선택적 가설 | 추격 없는 버전과 비교하는 짧은 실험 |
| 선택/분기/엔딩 수 | 보류 | 소규모 상태 변화가 플레이어에게 의미 있게 읽히는지 |
| MBV/RI 및 수치 임계값 | 미검증 | 실제 필요성이 확인되기 전 구현 금지 |
| 오디오·화면 왜곡 | 선택적 연출 | 정보 유지, 접근성, 강도 설정을 포함한 검수 |

## 과거 문서의 가설을 확정 사실로 취급하지 말 것

- 탐색 + 추격 + 선택지가 모두 필수라는 주장
- `뒤돌아보기 +5`, MBV/RI 점수나 임계값
- 정확히 6개의 엔딩
- 2D/2.5D/3D 시점 전환
- 특정 엔진이 이 프로젝트에서 무조건 가장 쉽거나 빠르다는 주장

## 최소 검증 단위 후보

- 한 화면 또는 작은 방
- 상호작용 대상 2–4개
- 서로 비교할 단서 2–3개
- 행동 후 관찰 가능한 세계/텍스트 반응 하나
- 재시작 방법 하나

이 후보도 최종 요구사항이 아니라 가장 작은 실험 출발점이다.

## 진행 보고 규칙

각 변경/실험 기록에는 목적, 변경 파일 또는 실험 범위, 실제 실행한 검사, 관찰 결과, 실패/미검증 부분, 다음의 가장 작은 작업을 남긴다. 실행하지 않은 테스트는 통과했다고 쓰지 않는다.
