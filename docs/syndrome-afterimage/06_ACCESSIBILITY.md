# 접근성 및 시청각 효과 체크리스트

접근성은 출시 직전의 장식 작업이 아니라 프로토타입에서 반복 확인할 품질 조건이다. WCAG 기준을 인용했다고 해서 실제 게임이 자동으로 준수하는 것은 아니다.

## 시각 효과

- [ ] 강한 깜박임·빠른 줌·심한 화면 흔들림을 기본값으로 넣지 않았다.
- [ ] 효과 감소/끄기 옵션이 실제 화면에서 작동한다.
- [ ] 효과를 줄여도 단서·위험·상호작용에 필요한 정보가 유지된다.
- [ ] 색상만으로 상태를 전달하지 않는다.
- [ ] 텍스트 대비·크기·줄 길이·읽기 시간을 확인한다.
- [ ] 애니메이션/잔상 때문에 버튼이나 조사 대상을 놓치지 않는다.

## 오디오

- [ ] 소리 재생은 사용자 입력 후 시작할 수 있다.
- [ ] 음악·효과음·환경음의 음량을 조절하거나 끌 수 있다.
- [ ] 갑작스러운 큰 음량을 피하고, 중요한 정보에 대체 시각/텍스트 큐를 제공한다.
- [ ] 소리가 꺼져도 진행에 필수적인 지시를 놓치지 않는다.
- [ ] 자막 또는 텍스트 설명이 필요한 음성 정보를 보완한다.

## 조작·상호작용

- [ ] 핵심 상호작용에 키보드만으로 접근할 수 있는지 확인한다.
- [ ] 포인터 사용이 가능한 상호작용에는 명확한 포커스/선택 상태가 있다.
- [ ] 상호작용 가능한 대상과 장식용 배경을 구별할 수 있다.
- [ ] 실패 후 재시작 방법이 명확하다.
- [ ] 반응 시간에 의존하는 구간은 위험을 미리 알리고 완화 방안을 검토한다.
- [ ] 화면 크기 변경과 모바일 브라우저에서 UI가 겹치지 않는다.

## 깜박임 관련 기준

WCAG 2.2의 2.3.1과 2.3.2는 서로 다른 성공 기준과 적합성 수준을 가진다. 단순히 “3Hz 미만이면 안전/준수”라고 결론 내리지 않는다. 실제 콘텐츠의 면적·밝기 변화·대비 및 관련 예외 기준을 포함해 공식 문서를 확인한다.

- [WCAG 2.2](https://www.w3.org/TR/WCAG22/)
- [Understanding SC 2.3.1: Three Flashes or Below Threshold](https://www.w3.org/WAI/WCAG22/Understanding/three-flashes-or-below-threshold)
- [Understanding SC 2.3.2: Three Flashes](https://www.w3.org/WAI/WCAG22/Understanding/three-flashes.html)

## 검사 기록

각 검사마다 빌드/브라우저/기기, 재현 단계, 예상 결과, 실제 결과, 문제 심각도, 수정 사항, 재검사 결과를 기록한다. 실제 빌드에 적용하지 않았다면 “접근성 검증 완료”라고 쓰지 않는다.
