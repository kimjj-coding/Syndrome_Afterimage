# 조사 로드맵과 의사결정 관문

이 문서는 **고정된 일정표가 아니라 근거 확인 단계**다. 사용자가 일정을 정하기 전에는 날짜를 임의로 정하지 않는다. 각 관문은 통과·수정·보류·중단으로 끝날 수 있다.

## 단계별 로드맵

| 관문 | 조사/실험 | 산출물 | 통과 조건 | 실패하면 |
|---|---|---|---|---|
| G0 — 범위 | 브라우저 목표, 예산, 기대 경험, 안전 기준과 비목표를 다시 확인 | 현황·위험 목록 | 플랫폼·예산·경험 목표가 서로 모순되지 않고 미결정 사항이 분리됨 | 다음 조사보다 범위 축소를 먼저 함 |
| G1 — 근거 감사 | 기존 보고서의 주장을 원출처와 대조 | 주장·출처 감사표, 근거 기록 | 핵심 주장에 열리는 URL, 출처 등급, 주장 범위가 기록됨 | 근거 없는 주장은 가설/보류로 낮춤 |
| G2 — 핵심 루프 | 2~3개 후보를 동일한 기준으로 비교 | 핵심 루프 비교표, 테스트 스크립트 | 한 번의 실험이 하나의 질문을 검증하며 스토리/엔진을 미리 확정하지 않음 | 단서 상호작용만 남김 |
| G3 — 상호작용 최소 버전 | 이동/클릭, 단서 2~3개, 세계 반응, 재시작 확인 | 프로토타입 체크리스트·관찰 기록 | 플레이어가 다음 행동을 추론하고, 단서와 반응을 설명할 수 있음 | 인터랙션 표시·단서·반응을 단순화 |
| G4 — 기술 검증 | 후보 프레임워크에서 같은 작은 씬을 실행 | 재현 가능한 POC 기록 | 빌드와 브라우저 실행이 되고 입력·상태·재시작·크기 변경을 확인함 | 더 간단한 기술 옵션 실험; 기능은 추가하지 않음 |
| G5 — 접근성·안전 | 왜곡·깜박임·사운드·자막/대체 큐·키보드·가독성 검수 | 정신건강·접근성 체크리스트 | 효과 감소 모드에서도 필수 정보와 상호작용 유지 | 위험한 효과 삭제/대체, 필요시 전문가 검토 |
| G6 — 서사·선택 | 루프가 검증된 뒤 단서와 선택의 연결 결정 | 선택·상태표 | 모든 선택에 목적과 관찰 가능한 반응이 있으며 테스트 가능 | 대규모 분기 대신 작은 상태 변화 사용 |
| G7 — 에셋·제작량 | 배경·스프라이트·애니메이션·음악·폰트·효과·라이선스 목록화 | 에셋 목록, 작업량 추정 | 사용 조건이 기록되고 작은 팀이 제작 가능한 범위 | 고유 에셋 수를 줄이거나 후순위로 미룸 |
| G8 — Copilot 명세 | 승인된 상호작용을 구현 명세와 테스트로 변환 | Copilot 지침, 인수 테스트 | 입력·상태 전이·출력·실패/재설정·테스트가 작성됨 | 구현 요청 전에 요구사항 보완 |
| G9 — 수직 슬라이스 | 검증된 루프를 짧은 플레이 가능 구간으로 묶어 테스트 | 빌드, 테스트 기록, 버그 목록 | 이해 가능하고 재현 가능하며 확장할 가치가 있음 | 범위를 줄이거나 핵심 루프 수정·중단 |

## 조사 우선순위

### P1 — 지금

1. 핵심 루프 후보 비교: 각 루프가 플레이어에게 무엇을 하게 하고 어떤 경험을 목표로 하는가?
2. 소수 사례의 실제 메커니즘 검토: 공식 소개, 직접 플레이 관찰, 리뷰 해석을 분리한다.
3. 정신건강을 진단·도덕 점수·폭력성 설명으로 오용하지 않는 원칙을 수립한다.
4. 접근성 표준을 실제 효과·상호작용 검사표로 바꾼다.

### P2 — 루프 후보가 테스트 가능해진 뒤

5. Phaser와 최소 Canvas/DOM 구현을 같은 기능 기준으로 비교하고, 필요할 때만 PixiJS를 추가한다.
6. 실제 브라우저/기기에서 사운드 시작, 저장·불러오기, 크기 변경, 키보드·터치 입력을 시험한다.
7. 에셋 제작량과 라이선스를 기록한다.

### P3 — 근거 관문을 통과한 뒤

8. 스토리·캐릭터·스테이지·엔딩을 작성한다.
9. Copilot을 활용해 작은 기능씩 구현하고 회귀 테스트한다.
10. 핵심 루프가 안정된 경우에만 추가 회차, 효과, 추격 AI 등을 검토한다.

## 의사결정 기록 형식

중요한 선택마다 날짜, 질문, 후보, 근거 URL, 사실/해석/가설 분류, 결정, 확신도, 비용·위험, 테스트, 통과 기준, 결과, 재검토 조건을 기록한다. 근거와 시험이 없는 선택은 임시안으로 남긴다.
