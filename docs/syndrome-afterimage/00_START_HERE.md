# 지금 무엇을 해야 하나? — 가장 짧은 실행 계획

**현재 결론:** 지금은 게임 전체를 기획하거나 엔진을 확정할 단계가 아니다. GitHub 기본 브랜치 `main`에는 현재 README만 확인되며, 실행 가능한 게임 코드나 빌드 설정은 확인되지 않았다. 따라서 다음 목표는 연구 문서를 더 늘리는 것이 아니라 **작은 웹 프로토타입을 시작할 수 있는 상태를 만드는 것**이다.

## 현재 상태를 한눈에

- **프로젝트 정체성:** 브라우저 기반 웹 게임 — 확정.
- **개발 환경:** GitHub 저장소는 존재하지만, `main`에서 게임 코드/실행 스크립트는 아직 확인되지 않음.
- **조사 문서:** 계획·상태 감사·상세 종합·접근성·기술 후보 등은 준비되어 있음.
- **미확정:** 엔진, 시점, 조작, 스토리, 변수, 엔딩 수.
- **검증되지 않은 옛 아이디어:** MBV/RI 수치, `뒤돌아보기 +5`, 6개 엔딩, 탐색+추격+선택을 모두 필수로 하는 구성.
- **이번 PR:** 문서 추가 제안일 뿐, `main`에 병합된 상태가 아님.

## 앞으로 할 일 — 순서대로

### 1. 문서 반영 PR을 한 번만 확인한다

[PR #1 열기](https://github.com/kimjj-coding/Syndrome_Afterimage/pull/1)

이 PR은 조사 문서를 주제별로 정리하고 Copilot 지침을 추가한다. 게임 코드는 바꾸지 않는다. 우선 이 문서 묶음을 저장소에 둘지 검토한다. 이해가 어려운 세부 내용은 지금 모두 읽을 필요가 없다. 이 페이지와 [프로젝트 상태](00_PROJECT_STATUS.md)만 먼저 보면 된다.

### 2. 저장소에 실행 가능한 웹 프로젝트가 있는지 확인한다

PR을 반영한 뒤 `main` 브랜치에서 아래를 확인한다.

- `package.json` 같은 프로젝트 설정 파일이 있는가?
- 실행 명령이 문서나 설정에 정의되어 있는가?
- Codespaces에서 실행하고 브라우저 미리보기를 열 수 있는가?

현재 `main`에서 확인한 파일 목록은 README 하나뿐이므로, 아직 프로젝트가 없다면 빈 프로젝트부터 만들어야 한다. 기존 파일이 나중에 발견되면 중복으로 새 프로젝트를 만들지 않는다.

### 3. 첫 프로토타입은 아주 작게 만든다

첫 실험의 목표는 완성된 공포 게임이 아니다.

- 한 화면 또는 작은 방
- 상호작용 대상 2–4개
- 단서 2–3개
- 조사 후 텍스트/환경 반응 하나
- 재시작 기능 하나

캐릭터 이동, 추격 AI, 엔딩 분기, 왜곡 효과, 저장 시스템은 이 실험에 필요하다고 확인되기 전까지 추가하지 않는다. 이 범위는 제안된 실험이지 최종 게임 기획이 아니다.

### 4. 엔진은 같은 기능을 만든 뒤 선택한다

초보자에게 유명하다는 이유만으로 Phaser를 확정하지 않는다. 필요한 경우 최대 두 후보만 비교하고, 같은 작은 기능을 실제로 실행해 설정 난도, 수정 난도, 재시작, 키보드/포인터 접근성을 기록한다.

### 5. 한 번에 하나만 결정한다

첫 프로토타입이 실행되고 나면 다음 질문에 답한다.

1. 플레이어가 상호작용 대상을 알아차리는가?
2. 단서 조사 후 무엇이 바뀌었는지 이해하는가?
3. 다음 행동을 추론할 수 있는가?
4. 어떤 부분이 헷갈리거나 구현하기 어려웠는가?

관찰 결과를 바탕으로 다음 기능 하나만 선택한다. 추격이나 선택지는 그 뒤에 비교 실험으로 검토한다.

## 완료라고 말할 수 있는 기준

첫 단계의 완료는 “보고서가 많아졌다”가 아니다. 저장소에서 웹 프로젝트가 실행되고, 플레이어가 단서 하나를 조사하면 반응 하나가 나타나며, 재시작이 실제로 작동하는 상태다. 실행 환경, 브라우저, 테스트 결과를 기록한 뒤에야 다음 기능으로 넘어간다.
